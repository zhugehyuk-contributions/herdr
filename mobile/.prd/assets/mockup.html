herdr mobile

herdr와 똑같은 구조를 폰으로. 리모트를 노드로 추가하면 각 노드의 스페이스가 보이고, 스페이스 안의 pane 하나하나가 터미널이다. agents는 pane들 위의 논리 뷰.

physicalremote ▸ space ▸ pane (= terminal) — tab은 pane 그룹핑 logical  agents = pane들의 상태 오버레이 (별도 뷰) — herdr 사이드바 대응 surface  pane 뷰 = ClientLaunchMode::TerminalAttach (이미 존재) — zoom 아님 (zoom은 Tab 공유·세션 영속 → 폰이 데스크톱을 줌시킴)
role herdr client for mobile — 기존 client → server 구조 그대로 stack Expo · React Native · repo herdr-mx/mobile/ transport embedded ssh (native module) — 기존 브리지 2종 무수정 재사용 frames bincode v2 셀 그리드 — ANSI 아님 → xterm.js 불필요 server 수정 5건 (전부 국소) — 게이트는 transport가 아니라 attach 정리

v6 — 무엇이 바뀌었나

베이스를 v0.8.0-mx.1(aa9f6e14)로 교체했다 — 구 베이스 feat/multi-remote-client는 v0.6.8로 mx보다 561커밋 뒤였고 multi-remote는 이미 상륙해 있었다(src/main.rs:550). 새 워크트리 .worktrees/feat-mobile-client, 게이트 green(clippy + nextest 3574/3574).

계획이 바뀐 지점 — v5는 “bincode를 TS로 포팅 + 네이티브 셀 렌더러”로 직행했다. 실측 결과 인코딩이 연결 모드와 직교해서, observe 클라이언트가 TerminalAnsi를 요청하면 이미 diff된 ANSI 바이트를 받는다 — 코덱 포팅 대부분이 사라지고 orca의 터미널 서브시스템이 거의 그대로 붙는다. 그리고 observe는 데스크톱 PTY를 리사이즈하지 않는다(headless.rs:1763) — v5가 attach로 감수하려던 비용이 사라진다.

핵심 — TerminalAnsi + ObserveTerminal

인코딩 분기는 연결 모드와 직교하다 — 모드가 FrameData를 만들고(headless.rs:4152), 그 뒤 인코딩이 직렬화한다(:4237). 그래서 observe 클라이언트도 RenderEncoding::TerminalAnsi를 요청할 수 있고, 서버는 BlitEncoder로 이미 diff된 ANSI 바이트를 보낸다(render_stream.rs:114). kitty 그래픽은 그 바이트 안에 인라인된다(render_stream.rs:109 insert_graphics_before_sync_end). 프로덕션 herdr attach가 이미 이 인코딩을 쓴다(client/mod.rs:2548).

→ 앱이 손으로 쓸 bincode 디코더는 envelope + Welcome + Terminal 3개뿐이다. CellData · FrameDelta · FNV-1a 체크섬 · raw deflate · 델타 재구성 전부 불필요하고, orca의 xterm WebView 서브시스템이 거의 그대로 붙는다.
