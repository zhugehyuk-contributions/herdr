# 12 · QR 로그인 (목표 조건 5)

**유저 지시 (2026-08-24, 축자)**:
> `5. qr 코드 로그인 기능 꼭 추가 (생각해보니 이거 필수임 ssh 접속 키 때문에)`

**이유가 요구사항의 일부다.** "ssh 접속 키 때문에" — 유저가 지목한 마찰은 **개인키**다.
지금 원격 하나를 붙이려면 settings의 11필드 폼에 **PEM 본문을 폰에서 타이핑**해야 한다
([[.prd/11-mockup-conformance]] P0). 이건 이미 P0로 기록돼 있었고, 조건 5는 그걸 필수로 승격한 것이다.

## ⚠️ Tensions — 목업의 페이로드는 유저가 말한 이유를 해결하지 못한다

목업 화면 ①(`assets/mockup.html:301-327`)이 스스로 정의하는 것:

> 페이로드 = `{name, ssh target, session…}` → 03 시트 프리필
> 인증은 ssh 그대로 (데스크톱 `--remote`와 동일) — **신규 페어링 프로토콜 없음**

즉 목업 QR은 **프리필 전용**이고 키는 여전히 사람이 넣는다. 11필드 중 쉬운 4개를 없애고
**어려운 1개를 남긴다.** 유저의 이유("키 때문에")와 정면으로 어긋난다.

목표 조건 2("모르겠으면 orca/목업 결정을 쓴다")는 **모를 때**의 규칙이지, 유저가 이유를 명시한
자리에서까지 목업이 이기는 규칙이 아니다. 그러므로 이 페이지는 승자를 조용히 고르지 않고
분기를 적어둔다 — 최종 판정은 유저.

## 선택지

| | 페이로드 | 스캔 1회로 붙나 | 위험 | 데스크톱 작업 |
|---|---|---|---|---|
| **A. 목업 그대로** | name·host·port·user·session | ❌ 키는 여전히 타이핑 | 없음 | QR 렌더만 |
| **B. 키를 싣는다** | A + **개인키 본문** | ✅ | QR이 곧 자격증명 — 화면 촬영·스크린셰어·스크린샷이 곧 셸 접근 | QR 렌더만 |
| **B′. 전용 키를 발급해 싣는다** (권고) | A + **herdr가 그 자리에서 만든 전용 ed25519 개인키** | ✅ | 노출 시 피해가 **그 키 하나**로 국한, 데스크톱에서 취소 가능 | 키 생성 + `authorized_keys` 추가 + QR 렌더 |
| **C. 역방향 등록** | 폰이 **자기 공개키**를 QR로 표시, 데스크톱이 읽어 등록 | ✅ | **QR에 비밀이 없다** (공개키는 촬영돼도 무해) | 데스크톱에 **카메라/스캐너가 필요** — herdr는 TUI다 |

**C가 보안상 가장 깨끗하지만 herdr에 스캐너가 없다.** 폰 화면의 공개키를 사람이 데스크톱으로 옮기는
것은 마찰의 방향만 뒤집는 것이라 조건 5를 만족하지 못한다.

**권고 = B′.** 유저가 말한 마찰을 실제로 없애면서, 노출 사고의 반경을 "유저의 개인 키" 대신
"폰 전용 키 1개, 언제든 취소 가능"으로 줄인다. 목업의 계약("인증은 ssh 그대로, 신규 페어링
프로토콜 없음")도 유지된다 — 새로 만드는 것은 프로토콜이 아니라 **키 하나**다.

### B′를 고를 때 반드시 함께 오는 것

- QR은 **자격증명**이다. 화면에 오래 띄우지 않는다(전용 뷰, 종료 시 소멸).
- 발급한 키의 `authorized_keys` 항목에 **기기 이름 주석**을 넣어 취소가 가능하게 한다.
- 페이로드에 **발급 시각**을 넣어 폰이 오래된 코드를 경고한다.
- ⛔ **유저의 실제 `~/.ssh/authorized_keys`에 쓰는 것은 비가역·보안 변경이다.** 기본값은 쓰지 않고,
  명시 플래그/확인을 거친다. 에이전트가 유저 머신에 대고 실행하지 않는다.

## 진행

### Q1 — 페이로드 스키마 + 파서 ✅ (2026-08-24)

`src/pairing/pairing-payload.ts`. 스키마 `{v, name?, host, port=22, user, session?, key?, issuedAt?}`.

- **`key`는 옵셔널로 남겼다.** B′가 확정됐어도 키 없는 코드는 목업의 프리필 폼 그대로 유효하고,
  그 경우 화면은 "에러"가 아니라 **키 칸만 빈 폼**에 착지한다. 이 선택이 Q4(데스크톱)의 구현 순서를
  Q1~Q3에서 분리한다.
- **파서는 절대 throw하지 않는다.** 카메라가 돌려줄 수 있는 것(URL·wifi 코드·잘린 프레임·미래 버전
  코드)이 전부 이 화면의 정상 답이다. JSON이 아니면 *"invalid JSON"*이 아니라
  *"herdr 코드가 아니다"* — 흔한 경우는 애초에 herdr 코드가 아닌 것이고, wifi QR을 두고 JSON을
  확인하라는 말은 무용하다.
- **버전은 방향까지 말한다**: 미래 코드면 "앱을 업데이트", 과거 코드면 "데스크톱 herdr을 업데이트".
- ⚠️ **실패 사유에 값은 절대 안 들어간다** — 그 값이 개인키일 수 있고 사유는 화면에 렌더된다.
  `remote-config.ts`의 규칙을 이어받되 여기서 더 날카롭다. 테스트가 이걸 고정한다(키가 불량 필드인
  경우에도 `BEGIN OPENSSH`가 사유에 없어야 한다).
- `pairingCodeStaleness`는 **만료가 아니라 경고**다(10분). 데스크톱이 여전히 받아주는 코드를 앱이
  거절하면 저쪽에 없는 규칙을 발명하는 것이다.

게이트: 유닛 13건, 114파일/984테스트.

### Q1 수정 — id가 키스토어에 저장 불가였다

`z@10.0.2.2:2222`는 읽기 좋고 **저장이 안 된다**: `remote-store.ts`가 id를 키스토어 키에 이어붙이며
`[A-Za-z0-9._-]{1,64}`로 제한하므로 `@`·`:`가 있으면 `saveStoredRemote`가 throw한다 — **파싱은 완벽히
됐는데 쓰기에서 죽는** 최악의 자리다. `pairingRemoteId()`로 분리해 sanitize+64자 절단, 테스트로 고정.
id는 내부 핸들이고 사람이 읽는 것은 `name`이다.

### Q3 — 폼으로의 인계 ✅ (2026-08-24)

`src/pairing/pairing-handoff.ts` (한 칸짜리 인메모리 슬롯) + `draftFromPairing` + settings의 소비 effect.

- **라우트 파라미터를 쓰지 않는다.** expo-router의 params는 네비게이션 상태·딥링크 히스토리·라우트를
  찍는 모든 로그에 남는다(`pane-deep-link.ts`가 바로 그 성질 위에 서 있다). 개인키를 실을 수 있는 값이
  **주소의 일부가 되는 것**만은 안 된다.
- `take()`가 **읽으면서 지운다** — 두 번째 호출자는 `null`. 개인키가 세션 내내 모듈 슬롯에 앉아 있지
  않는다는 게 이걸 store가 아니라 handoff로 만드는 성질이고, 테스트가 그걸 고정한다.
- **저장이 아니라 폼을 연다.** 코드가 필드를 주고 사람이 누름을 준다. 그 누름 위에서만 기존 검증·
  호스트키 경고·프로브(#9)가 돈다.
- `allowUnknownHostKey`는 **false로 남긴다.** 코드는 타깃과 키를 나르지만 "신원이 고정되지 않은 호스트에
  붙겠다"는 유저의 결정은 나르지 않는다. 사진 한 장을 근거로 앱이 보안 질문에 답하는 셈이 된다.

### Q4 — 데스크톱 `herdr pair` ✅ (2026-08-24)

`src/cli/pair.rs`(1186줄) + `src/cli.rs`·`src/cli/spec.rs` 배선 + `qrcode 0.14.1`(default-features off —
`image`/`svg`가 딸려오는 걸 막았고 락에 패키지 1개만 추가). **명령 이름은 `herdr pair`** —
목업/이 문서가 쓰던 `show qr`은 사이드바 컨텍스트 메뉴(별도 UI 작업)이고, 폰 화면 안내도
**사람이 오늘 실제로 칠 수 있는 것**으로 맞췄다(없는 메뉴 항목을 가리키는 안내는 없느니만 못하다).

- **키 발급은 `ssh-keygen` 위임** — herdr 바이너리에 crypto 크레이트를 안 늘린다. tmp 키 파일 2개는
  Drop 가드로 성공·실패 양쪽에서 삭제(실측: `/tmp`에 잔여 `herdr-pair-*` 0개).
- **`--authorize`는 ssh 원격에 대해 거부(exit 2)** — 폰은 *그* 호스트로 다이얼하는데 이 프로세스는
  *이* 머신의 `authorized_keys`만 쓸 수 있다. 쓰면 엉뚱한 박스를 인가한다. (`pair.rs:558`)
- **append-only가 구조로 보장된다**: `authorized_keys_addition()`이 *추가분* 또는 `None`만 돌려주고
  치환을 만드는 경로가 없다. `0600`은 생성 시에만, 기존 파일의 권한은 안 건드린다. 중복 판정 키는
  **comment**(`herdr-mobile/<device>`)라 같은 기기 재실행이 줄을 쌓지 않는다.
- 원격 목록은 **돌고 있는 서버**(`Method::RemoteList`)에서 — 사이드바와 같은 출처. 서버 에러와
  "원격 없음"을 구분해서 에러를 빈 레지스트리로 보고하지 않는다.
- 기본 실행은 **아무것도 쓰지 않는다**(실측: `~/.ssh` 생성조차 안 됨). 공개키 한 줄을 찍고
  `--authorize`를 안내한다.

**nextest 4000건 전부 green**(베이스라인 3981 → +19).

저장 가능성(`id`가 키스토어 charset)까지 같은 테스트가 본다 — **파싱 성공과 저장 성공은 다른 일이다.**

### Q5 — QA ✅ (2026-08-24, 7차, 별도 에이전트 PASS)

**키 본문은 화면 어디에도 없다**(길이 표시조차, 텍스트에 `BEGIN OPENSSH` 0건).

## ⛔ iOS 빌드 파손 — `expo-camera`를 넣은 뒤 Pods 프로젝트가 안 열린다 (2026-08-24)

**조건 5의 폰 절반이 iOS에서 빌드되지 않는다.** Android는 같은 커밋에서 크래시 0건으로 7차 PASS.

### 실측

```
xcodebuild … -workspace herdr.xcworkspace
  → -[XCRemoteSwiftPackageReference _setSavedArchiveVersion:]: unrecognized selector
  → The project 'Pods' is damaged and cannot be opened
  → 에러 238건 (208건이 modulemap 부재, Foundation·Darwin 같은 시스템 모듈까지)
```

`xcodebuild -project Pods/Pods.xcodeproj -list` **단독으로도 같은 예외** → 파일 자체가 안 열린다.
**`pod deintegrate` + `Pods`/`Podfile.lock` 삭제 후 재설치해도 동일**(`pod install` 자체는 exit 0).

### 판별

| | `qa-ios-n1`(00:25, camera 없음) | `qa-ios-8`(HEAD, camera 있음) |
|---|---|---|
| `Pods.xcodeproj -list` | **열린다** | **예외** |
| SPM refs | 10 | 8 |
| Xcode | 26.6 (동일) | 26.6 |

두 워크트리의 델타는 **`expo-camera` 하나**다(같은 `with-herdr-ssh-spm.js`, 같은 Xcode).
[가설] 인과는 그 델타지만 camera를 빼서 재현을 뒤집어보진 않았다.

### 유력한 실마리 — `pod install`이 스스로 경고한다

```
[SPM] WARNING!!! Pod HerdrSsh is using swift package(s) Citadel, NIOSSH with static linking,
this might cause linker errors. Consider using USE_FRAMEWORKS=dynamic
```
CocoaPods가 만든 프로젝트에 SPM 참조(Citadel/NIOSSH)가 **정적 링크**로 섞여 있는 상태이고,
팟이 하나 늘자 그 조합이 깨진 것으로 보인다. 후보 수리: `USE_FRAMEWORKS=dynamic pod install`
(RN 문서화된 우회) 또는 `plugins/with-herdr-ssh-spm.js`의 주입 방식 변경.

### 내가 멈춘 지점

빌드 3회 실패. 진단은 확정(위 실측), 수리는 **링크 방식 변경**이라 앱 전체에 영향이 가는 결정이므로
여기서 멈춘다. `USE_FRAMEWORKS=dynamic`은 HerdrSsh 네이티브 모듈의 링크도 바꾼다 —
M2b에서 그 모듈이 조용히 미링크됐던 전례가 있어(`.prd/10` §빌드) 가볍게 켤 값이 아니다.

**이것이 조건 3(iOS QA)의 현재 블로커다.** 카메라 없이 빌드되던 `qa-ios-n1`(N1 9차 PASS)이
마지막으로 성공한 iOS 리그다.
